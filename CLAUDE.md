# @krometra/easy-data-scroll

Виртуальный бесконечный скролл для чатов и лент с элементами разной высоты, без прыжков. Два режима, как `scrolling.mode` у DevExpress: `infinite` (догрузка у края через `loadBefore`/`loadAfter`) и `virtual` (ползунок на весь список, строки по номерам через `loadRange(from, to)`). Ядро на чистом DOM без зависимостей, тонкие адаптеры для Vue, React и Angular. Цель: подключается в любой фреймворк и работает очень быстро. Как устроено и почему не прыгает, описано в `README.md`, раздел «Почему не прыгает».

## Стек

- TypeScript 7 (нативный `tsc`), Vite 8 (трансформ через Oxc), Vitest 5, Playwright 1.64.
- Сборка библиотеки: просто `tsc -p tsconfig.build.json` в `dist/` (ESM + d.ts), без бандлера.
- Пакет `@krometra/easy-data-scroll`, репозиторий `github.com/krometra/easy-data-scroll` (публичный, оформлен по образцу `krometra/ui-kit`). Адаптеры подпутями: `/vue`, `/react`, `/angular`. Фреймворки — необязательные peer-зависимости.
- Витрина на GitHub Pages (<https://krometra.github.io/easy-data-scroll/>) собрана на `@krometra/ui-kit` (dev-зависимость, только для демо). Деплой — workflow `pages.yml` на push в `main`.
- Публикация в npm — workflow `publish.yml` по тегу `v*` через Trusted Publishing (OIDC, на npmjs.com у пакета указан `krometra/easy-data-scroll` и `publish.yml`), секрет не нужен; уже опубликованную версию пропускает. Секретов на уровне организации нет, `NPM_TOKEN` кита лежит в его собственном репозитории. Выпуск: версия в `package.json`, раздел «Что изменилось в X.Y.Z» в `README.md`, коммит `Версия X.Y.Z: ...`, тег `vX.Y.Z`, push тега.
- В исходниках относительные импорты с `.js` (`from './core.js'`), иначе webpack 5 и Node не разрешат `dist` при `"type": "module"`.
- Комментарии в коде не писать.

## Запуск и проверка

```bash
npm run dev          # http://localhost:5179
npm run check        # типы + vitest + сборка + e2e (Chrome и WebKit), всё должно быть зелёным
npx playwright test -g "прыжок" --project webkit   # один тест в одном движке
```

- В песочницах доступны `window.list` (экземпляр ядра) и `window.backend`, параметры страницы: `?latency=мс&live=0&fail=0.3`.
- Сборка витрины как на Pages: `BASE=/easy-data-scroll/ npm run build:demo`, посмотреть `npx vite preview --base /easy-data-scroll/`. Ссылки между страницами только относительные (`./chat.html`).
- Chrome в тестах системный (`channel: 'chrome'`, отдельный headless-процесс), WebKit из Playwright.
- Готово, только если `npm run check` зелёный в обоих движках и в демо счётчики «…во время скролла» и «Сдвигов содержимого» равны 0.

## Инварианты ядра (не ломать)

- Высота обёртки `.eds-item` всегда равна модели (`entry.height`). Содержимое меряется отдельно через `ResizeObserver` на `.eds-host`, изменения применяет только `applyHeights`.
- Ничего неизмеренного в список не попадает: новое рендерится в `.eds-measure`, ждёт медиа и только потом вставляется.
- Зоны изменения: `far` (дальше экрана) — бесплатно; `visible` — без поправки; `near` (между экраном и началом отсчёта) — поправка `pos += Δ`, а пока пользователь крутит (`isBusy`), откладывается в `pending`/`queue` до паузы.
- Во время прокрутки `scrollTop` пишется только в двух случаях: отложенный элемент вот-вот станет видимым и пачка снизу у края при оторванном от низа списке (там инерция всё равно кончилась). Счётчики `stats.busyWrites` и `stats.shift` — для тестов.
- Высоты округляются вверх до целого пикселя (`snap`): WebKit держит `scrollTop` целым, дробные поправки давали сдвиг на 1px.
- Режим `virtual`: незагруженное хранится записями-пропусками (`gap: true`, `count` строк, оценочная высота) прямо в `Layout`. Номер строки — `layout.rowOf(i)`, запись по строке — `indexAtRow(r)`. Ключей у пропусков нет, в `keys` и кэш узлов они не попадают.
- Разница высот в зоне `near` сначала поглощается пропусками между экраном и началом отсчёта (`absorb`), и только остаток идёт в `scrollTop`. Высоты пропусков остаются целыми.
- Пришедшие строки (`fillRows`) встают с оценочными высотами, сумма которых равна вырезанному куску пропуска, а потом `applyFill` применяет настоящие. Что компенсировать, решает по порядку: закреплённая строка после `scrollToIndex` (`pin`, снимается колесом, касанием, нажатием, клавишей), первая видимая загруженная строка со стороны начала отсчёта, иначе зоны.
- Выгрузка (`trimLoaded`) сворачивает далёкие строки в пропуск с их точной суммарной высотой и не трогает отрендеренный диапазон `[rs, re)`.
- Пропуски в зоне `far` подгоняются под среднюю высоту (`rescaleFar`), чтобы ползунок был честным. Ближние не трогаются.
- Рисунок плашек неподвижен относительно экрана: `paintPattern` копит в `pattern` сдвиги, которые сделала сама библиотека (не пользователь), и выставляет каждому видимому пропуску `background-position-y`. Шаг рисунка `--eds-row` общий на корне и меняется только когда плашек на экране нет. После прихода данных фаза ставится сразу (`loadRows`), иначе WebKit успевает нарисовать кадр с новыми элементами без фазы.

## Грабли

- `ResizeObserver loop completed with undelivered notifications`: появлялось, когда следили за высотой `.eds-content` и вызывали `observe()` внутри колбэка RO. Сейчас RO стоит только на viewport, а новые элементы внутри колбэков подписываются в следующем кадре (`observe` → `flushObserve`).
- Детектор сдвигов в тестах и в панели демо обязан вычитать собственные поправки библиотеки (`stats.shift`). Иначе компенсация при вставке снизу выглядит как «прыжок» на тысячи пикселей.
- `scrollToIndex`/`scrollToKey` двигают содержимое намеренно, детектор считает это сдвигом. В тестах после программного прыжка звать `resetJumps(page)` и копить сдвиги шагов в массив, а не сбрасывать.
- Поймать, откуда сдвиг: `W.__debugJumps = true` пишет в консоль кадр со сдвигом (`dPos`, `dShift`, `dH`, `W.__phase`). Приватные методы ядра (`applyFill`, `applyHeights`, `rescaleFar`, `trimLoaded`) можно обернуть из `page.evaluate` и логировать `dTotal`/`dPos`: так нашли картинки, догрузившиеся позже `mediaTimeout`.
- Демо-картинки отдаются с задержкой до 1 с, а dev-сервер работает по HTTP/1.1 с лимитом Chrome в 6 соединений. После прыжка в `virtual` разом грузятся ~80 сообщений, и картинки не успевали за 1,5 с: сообщение росло уже на экране. В виртуальном демо `mediaTimeout: 3000`.
- «Контент скачет» при долгой загрузке оказался прыжком серых плашек, а не сообщений: рисунок был привязан к верхнему краю огромного пропуска и к его собственному шагу `height/count`, который менялся при каждом поглощении. Детектор сдвигов следит только за `.eds-item`, поэтому для плашек есть отдельный `trackSkeleton` (фаза рисунка на экране между кадрами). Увидеть такое помогает видео: `recordVideo` в Playwright, кадры через `ffmpeg ... tile=6x1`, жесты прокрутки Chrome через CDP `Input.synthesizeScrollGesture` (с инерцией, в отличие от `mouse.wheel`).
- Chrome считает раскладку во float32: целые выше 2^24 = 16 777 216 px округляются до чётных. 100 000 сообщений по ~165 px дают ~16,5 млн, при пересчёте оценок высота переваливала предел, и экран сдвигался ровно на ±2px (модель и DOM расходились на 2px). Поэтому `virtual` держит высоту не больше `MAX_HEIGHT` = 15 млн px, сжимая оценку незагруженных строк (`rowEstimate`). На голых страницах с теми же размерами ниже предела сдвига нет, проверено.
- `vue-tsc` не работает с TypeScript 7 (нативный tsgo без JS API), поэтому шаблоны Vue в репозитории не проверяются. Вывод дженериков проверен так: `npm pack`, отдельный проект с `typescript@5.9`, `vue-tsc@3`, `vue`, в нём `.vue` с `<InfinityScroll :load-range>` и обращением к несуществующему полю `item` — должна быть ошибка типа. Тип Vue-компонента повторяет то, что сам `vue-tsc` генерирует для `<script setup generic>` (функция с `__ctx`), именно эту форму понимает Volar.
- `angularRenderer` выводит тип из входа компонента. Сигнальный вход — `InputSignalWithTransform<any, infer W>`: с `unknown` на первом месте вывод не срабатывает (тип инвариантен).
- Первую версию пакета через Trusted Publishing не выпустить: привязку к GitHub Actions npm даёт настроить только у существующего пакета. 0.1.0 вышла по тегу с временным granular-токеном (обход 2FA, только `@krometra`, 7 дней) в секрете `NPM_TOKEN`; после настройки Trusted Publishing секрет удалён, токен отозван, 0.2.0 вышла уже через OIDC.
- npm: локальная публикация без 2FA отвечает 403 («Two-factor authentication or granular access token with bypass 2fa enabled is required»); вход из CLI шлёт код на почту каждый раз, а ссылка входа протухает за пару минут. Настройка Trusted Publisher требует пароль и 2FA ключом: делать в локальном Chrome (CDP на 9223), в Docker-браузере (9222) ключи безопасности и Touch ID не работают. Учётка и коды восстановления — `~/Projects/servers-info/accounts/npm.md`.
- Angular-демо работает в JIT без CLI: сигнальные `input()`/`viewChild()` там не распознаются (NG0951), поэтому в демо декораторы `@Input`/`@ViewChild`. С Angular CLI сигнальные API работают.
- React: `flushSync` нельзя вызывать внутри эффектов, поэтому `commit` откладывает его в `queueMicrotask` (до отрисовки кадра).
- Браузеры Playwright с `cdn.playwright.dev` качаются по таймауту. Работает зеркало: `PLAYWRIGHT_DOWNLOAD_HOST=https://playwright.download.prss.microsoft.com/dbazure/download/playwright npx playwright install webkit`.
- Firefox из Playwright 1.64 на macOS 27 не стартует («Could not find profile folder», в том числе вне песочницы). Firefox автотестами не покрыт, проверять руками.
- Процессы (vite и т. п.) убивать только по PID: `lsof -tiTCP:5179 -sTCP:LISTEN`, проверить `ps -p`, затем `kill <pid>`.
